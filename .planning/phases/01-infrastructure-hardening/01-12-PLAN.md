  <name>Change comparison operators for DESC ordering</name>
  <files>backend/core/pagination.py</files>
  <action>
In apply_cursor_pagination function (lines 54-59), change the comparison operators from `<` to `>`:

Before (lines 56-57):
```python
        or_(
            timestamp_column < cursor_timestamp,
            (timestamp_column == cursor_timestamp) & (id_column < cursor_id),
        )
```

After:
```python
        or_(
            timestamp_column > cursor_timestamp,
            (timestamp_column == cursor_timestamp) & (id_column > cursor_id),
        )
```

Reasoning from UAT diagnosis: All list endpoints (alerts, strategies, trades) use ORDER BY timestamp DESC, id DESC. For descending order, we want records that come AFTER the cursor in the result set. In DESC ordering, "after" means records that would appear later in the sorted result. The current `<` operator is correct for ASC ordering but wrong for DESC. For DESC, we need `>` to get the next page.

The UAT test showed: Page 1 returns IDs [8,7,6] with cursor=6. Page 2 should return [5,4,3] but instead returns [8,7,6] again. This indicates the WHERE clause is not correctly filtering for DESC order.
