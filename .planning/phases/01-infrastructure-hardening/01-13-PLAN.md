<task type="auto">
  <name>Task 1: Fix login rate limit check</name>
  <files>backend/api/auth.py</files>
  <action>
    In the login endpoint (lines 166-191), the code currently does:

    ```python
    allowed = await check_rate_limit(email_limit_key, 5, 60)
    if not allowed:
        raise HTTPException(status_code=429, ...)
    ```

    This is WRONG because check_rate_limit now:
    - Raises RateLimitException (429) when limit exceeded
    - Raises ServiceUnavailableException (503) when Redis unavailable
    - Returns True on success (but caller should not check this)

    Fix by removing the boolean check entirely. The exceptions will propagate
    and be handled by the global exception handlers registered in main.py.

    Change from:
    ```python
    allowed = await check_rate_limit(email_limit_key, 5, 60)
    if not allowed:
        logger.warning("Login rate limit exceeded for email %s", request.email)
        raise HTTPException(
            status_code=status.HTTP_429_TOO_MANY_REQUESTS,
            detail="Too many login attempts. Please try again later."
        )
    ```

    To simply:
    ```python
    await check_rate_limit(email_limit_key, 5, 60)
    ```

    The RateLimitException and ServiceUnavailableException are already registered
    with FastAPI's exception handlers (from 01-09), so they will return proper
    429/503 responses with Retry-After headers.

    DO NOT add try/except around the call - let exceptions propagate naturally.
  </action>
  <verify>
    1. grep -n "if not allowed" backend/api/auth.py should return nothing
    2. grep -n "await check_rate_limit" backend/api/auth.py shows the call without assignment
    3. Start server and test: curl -X POST http://localhost:8000/api/auth/login -H "Content-Type: application/json" -d '{"email":"test@test.com","password":"test"}' should NOT return 429 (should return 401 for invalid credentials)
  </verify>
  <done>Login endpoint calls check_rate_limit without boolean check, allowing exceptions to propagate for proper 429/503 handling</done>

    Create a test file that verifies the rate limiter integration works correctly.

    Tests to include:
    1. test_login_succeeds_under_rate_limit - Normal login attempt should not be blocked by rate limiter
    2. test_login_blocked_when_rate_limit_exceeded - After N failed attempts, should get 429
    3. test_rate_limit_uses_exceptions - Verify check_rate_limit raises exceptions (mock Redis)

    Use pytest-asyncio and mock the Redis client for deterministic testing.

    ```python
    """Tests for auth rate limiting integration."""

    import pytest
    from unittest.mock import AsyncMock, patch
    from fastapi.testclient import TestClient

    from core.rate_limit import check_rate_limit, RateLimitException, ServiceUnavailableException
    from core.exceptions import RateLimitException as CoreRateLimitException


    @pytest.mark.asyncio
    async def test_check_rate_limit_raises_on_exceeded():
        """check_rate_limit should raise RateLimitException when limit exceeded."""
        with patch("core.rate_limit.get_redis") as mock_get_redis:
            mock_redis = AsyncMock()
            mock_redis.incr.return_value = 10  # Over limit of 5
            mock_redis.expire.return_value = True
            mock_get_redis.return_value = mock_redis

            with patch("core.rate_limit._using_fake_redis", False):
                with pytest.raises(CoreRateLimitException):
                    await check_rate_limit("test_key", 5, 60)


    @pytest.mark.asyncio
    async def test_check_rate_limit_passes_under_limit():
        """check_rate_limit should return without exception under limit."""
        with patch("core.rate_limit.get_redis") as mock_get_redis:
            mock_redis = AsyncMock()
            mock_redis.incr.return_value = 3  # Under limit of 5
            mock_redis.expire.return_value = True
            mock_get_redis.return_value = mock_redis

            with patch("core.rate_limit._using_fake_redis", False):
                result = await check_rate_limit("test_key", 5, 60)
                assert result is True


    @pytest.mark.asyncio
    async def test_check_rate_limit_raises_service_unavailable_when_redis_down():
        """check_rate_limit should raise ServiceUnavailableException when Redis unavailable."""
        with patch("core.rate_limit.get_redis") as mock_get_redis:
            mock_get_redis.return_value = None  # Simulate Redis down

            with patch("core.rate_limit._using_fake_redis", False):
                with pytest.raises(ServiceUnavailableException):
                    await check_rate_limit("test_key", 5, 60)
    ```
